1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
This release establishes complete parity between the MagicAI Mobile App Explore
tab (118 tools across 17 functional categories) and the MagicAI web dashboard.
In addition to resolving previously reported screenshot bugs (Invoices, Studio,
and Archived Posts), this update adds full native create, edit, delete, and payment
recording features for all Sales tools (Invoices, Payments, Proposals, Estimates),
making all options available on web panel directly accessible in the mobile app.


2. SALES TOOLS FULL PARITY (INVOICES, PAYMENTS, PROPOSALS, ESTIMATES)
--------------------------------------------------------------------------------
[FEATURE 1] Sales Invoices (dashboard/user/sales/invoices)
  - Flutter & Backend parity:
    * Native "Create invoice" button in page header and empty state.
    * Full modal creation/editing form with auto-generated document numbers (INV-xxxxx),
      currency selection, customer company dropdown, contact dropdown, deal dropdown,

      - Payment amount with decimal validation.
      - Currency selector.

3. SCREENSHOT & PREVIOUS CRITICAL BUG FIXES
--------------------------------------------------------------------------------
[BUG 1] Invoices Screen (Stat cards unlabeled, empty state rendered as a table row)
  - Root Cause:
    1. KPI summary cards were parsed without their preceding section labels.
    2. Empty database results rendered as an empty single-cell <tr> with colspan,
       which the parser treated as a regular data row.
    3. Flutter module registry routed 'invoices' to fallback generic schema
       handling without metric fallback keys.
  - Fix:
    * Flutter (lib/screens/native_module_screen.dart):
      Mapped 'invoices', 'payments', 'proposals', and 'estimates' to NativeWorkspaceScreen.
    * Flutter (lib/screens/native_workspace_screen.dart & schema_components.dart):
      Added fallback resolution for stat metrics: metric['label'] ?? metric['title'].
    * Flutter (lib/screens/schema_components.dart & native_module_screen.dart):
      Added support for 'empty_state' schema type using WorkspaceEmptyState widget.
    * Backend (app/Services/Mobile/NativeMarkupParser.php):
      Enhanced KPI card parser to extract text labels from preceding <div> elements.
      Added detection for single-cell colspan empty rows and emitted structured
      {type: 'empty_state', title: ..., message: ...} instead of malformed table rows.
    * Backend (app/Services/Mobile/NativeScreenService.php):
      Mapped all sales routes:
      - 'dashboard.user.sales.invoices.index' => 'invoices'
      - 'dashboard.user.sales.payments.index' => 'payments'
      - 'dashboard.user.sales.proposals.index' => 'proposals'
      - 'dashboard.user.sales.estimates.index' => 'estimates'

[BUG 2] Studio Screen (Multiple overlapping states, button text "Save Saving...")
  - Root Cause:
    1. Transient Alpine.js progress nodes (x-show="saving", "!loaded", etc.) were
       being captured as visible text by the HTML parser, causing "Save Saving...".
    2. Flutter UI did not enforce mutually exclusive states; loading, error banner,
       and record views could render simultaneously.
  - Fix:
    * Flutter (lib/screens/native_workspace_screen.dart & native_module_screen.dart):
      Added deduplication logic in WorkspaceRecordEditor and NativeSchemaForm to
      clean concatenated labels into clean "Saving…" / "Save".
    * Flutter (lib/screens/native_extension_screen.dart):
      Enforced single-state rendering model: displays RetryPanel when errors occur
      with empty records; secondary banners only appear when cached data exists.
    * Backend (app/Services/Mobile/NativeMarkupParser.php):
      Filtered out transient Alpine state nodes using XPath:
      not(starts-with(@x-show, "!")) and contains(@x-show, "saving|submitting|loading|cropSaving|!loaded|x-cloak").

[BUG 3] Archived Posts Screen ("Could not be loaded" failure)
  - Root Cause:
    Mobile client queried /api/mobile/workspace/record with module_id='archived_posts'
    without required date boundaries ('from', 'until'), causing 500 Unprocessable Entity.
  - Fix:
    * Flutter (lib/screens/native_workspace_screen.dart):
      Added automatic ISO-8601 UTC date window generation for scheduled and archived feeds.
    * Backend (app/Services/Mobile/NativeWorkspaceService.php):
      Tolerates null date ranges and falls back to latest published posts.
